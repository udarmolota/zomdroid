Quick start

Zomdroid is a launcher: it runs your own copy of Project Zomboid on Android. The game itself is not included.

  1. You need to own Project Zomboid on Steam.
  2. Get the Linux game files. The fastest way is DepotDownloader on a PC; without a PC, use Download from Steam in the side menu. See Getting the game files.
  3. Pack the files into a .zip archive with the game files at the top level. See Packing the files.
  4. On the main screen tap +, enter a name, pick the preset that matches your game build and select the .zip. Build 41 needs 4 GB of RAM or more, Build 42 at least 6 GB, Build 42.12 and later at least 8 GB.
  5. Zomdroid picks the renderer and driver for your phone by itself. If you changed the settings and something broke, open the instance settings (gear icon) and tap Suggested preset.
  6. Tap Play. The first launch takes longer while the game builds its caches.

Something went wrong? See Reporting a problem.

Getting the game files

Zomdroid needs the Linux version of Project Zomboid, and you need to own the game on Steam or GOG. Pick one of the ways below; a download from Steam is then packed into a .zip archive.

1. On a PC with DepotDownloader (fastest)

DepotDownloader downloads any build of the game straight from Steam. On a PC it is much faster than downloading on the phone.

Guide for DepotDownloader
  1. Download DepotDownloader. For Windows, grab DepotDownloader-windows-x64.zip.
  2. Extract it anywhere, for example: C:\DepotDownloader
  3. Open the folder, right-click → Open in Terminal / CMD
  4. For the latest public version you need only -app and -depot, no manifest or beta. Replace YOURUSERNAME and YOURPASSWORD with your Steam credentials:

    ./DepotDownloader -app 108600 -depot 108603 -username YOURUSERNAME -password YOURPASSWORD

    For an older or beta build, add -manifest MANIFESTNUMBER and, if needed, a -beta flag (e.g. -beta unstable or -beta legacy_42_12). The exact command can be copied from SteamDB: select DepotDownloader from the "Copy format" menu and click the copy icon next to the desired build. Steam Mobile authentication may be required.
  5. When the download finishes, the console shows the folder with the files. Pack them as described in Packing the files and copy the .zip to your phone.

2. In the app: Download from Steam

No PC needed, but the download on the phone is slower.

  1. Open the side menu and tap Download from Steam, tab Game.
  2. Choose Build 41 or Build 42 and sign in with your Steam account. Your login goes to Steam only and is not stored. Approve the sign-in in the Steam app or enter the Steam Guard code.
  3. When asked, allow All files access: the game is saved into the public Downloads/zomdroid folder.
  4. Wait. Build 41 is about 6–7 GB and Build 42 about 10–11 GB. If the download stops, start the same build again and it resumes.

To get an older version instead of the latest, find it on SteamDB, copy its DepotDownloader line and paste the whole line into the manifest field.

The files end up in Downloads/zomdroid/ProjectZomboid_B41_… or …_B42_…. Inside there are three items: the projectzomboid folder, a .zomdroid_complete… file and projectzomboid.sh. Zomdroid does not create an instance from this folder yet: pack the contents of projectzomboid into a .zip first, see below.

3. From GOG

GOG sells Project Zomboid without DRM, and its Linux version comes as one installer file (.sh).

  1. Open the side menu and tap Download from GOG. Sign in with your GOG e-mail and password on GOG's own page: Zomdroid never sees your password.
  2. Signing in through a linked account, such as Google, does not work inside an app. If that is how you normally log in, set a GOG password first: gog.com → Sign in → Password reset.
  3. Tap Check library. Project Zomboid appears as a card.
  4. Tap Download. The installer is saved into the public Downloads/zomdroid folder; allow All files access when asked. You can switch to other apps meanwhile. If the download stops, tap the button again to continue.
  5. When the download is done, the button becomes Create an instance: it opens the new-instance screen with the installer already selected, no .zip needed.
On a PC

In your library on gog.com, download the Linux installer (the .sh file). Pack it into a .zip archive on its own, copy it to the phone and select that .zip when you create an instance. The .zip is needed because file managers do not reliably hand a bare .sh file to apps.

4. Packing the files into a .zip archive

The .zip archive must contain the game files at the top level, not inside a folder: ProjectZomboid64.json, java/, natives/ and the rest must be right inside the archive.

On the phone: in your file manager open Downloads/zomdroid/ProjectZomboid_…, then the projectzomboid folder inside it. Select everything inside that folder and compress it into a ZIP archive: not 7z or rar, and not the folder itself from the outside. The archive needs several more gigabytes of free space.

On a PC

Open the folder with the game files (the one with the ProjectZomboid64 executable). On Linux it is usually ~/.local/share/Steam/steamapps/common/ProjectZomboid/projectzomboid. With DepotDownloader it is the folder shown in the console when the download finishes, e.g. on Windows C:\Program Files (x86)\Steam\steamapps\content\app_108600\depot_108603\projectzomboid. Select all files (Ctrl + A, or Command + A on macOS) and add them to a .zip archive.

Put the .zip anywhere convenient and select it when you create an instance. After that you can delete the downloaded folders: they take up a lot of space. Keeping the .zip is not required, but it is handy later to reinstall or to create another instance of the same version, for example one with a virtual keyboard instead of gamepad controls.

Multiplayer libraries for Build 41

Multiplayer in Build 41, both joining servers and hosting, needs two extra libraries:

  • libRakNet64.so
  • libZNetNoSteam64.so

The game's developers ship them in the android folder of the Linux Build 42.12. Only these two files from that folder are needed.

Install them in the instance settings, card Additional libraries:

  • From Steam downloads just these two files with your Steam account.
  • From file takes a .zip you prepared earlier, with the two .so files at the top level. You can also add that .zip when you create the instance.

Without these libraries server hosting cannot be turned on for Build 41. Build 42 already includes them.

Renderers and drivers

A renderer translates the game's desktop graphics for Android. Zomdroid picks one for your phone when you create an instance; you can change it in the instance settings.

GL4ES

The most stable renderer for Build 41. In Build 42 it often shows graphical artifacts.

NG_GL4ES

For Build 42 on any GPU, with no driver needed. Zomdroid selects it on phones without a Snapdragon (Adreno) GPU. If you enabled the ANGLE driver for ZINK experiments, turn it off for NG_GL4ES: with ANGLE the frame rate drops sharply.

ZINK (ZINK_ZFA, ZINK_OSMESA)

The best picture on Build 42 with a Snapdragon (Adreno) GPU. ZINK needs a Vulkan driver; on Adreno Zomdroid selects ZINK_ZFA with a driver that suits your GPU. On other GPUs ZINK only works through ANGLE and is hard to set up, so use NG_GL4ES there.

Texture compression (ETC2)

On by default for NG_GL4ES and ZINK. It compresses large textures with minimal quality loss, which saves a lot of memory. The first launch builds a cache and takes longer; the cache can be cleared in the instance settings.

Vulkan drivers for ZINK

Freedreno and Turnip are builds of the same open-source Mesa driver for Adreno GPUs, tuned for different generations. If the picture looks wrong, try another driver.

  • Freedreno: default for Adreno 7xx (Snapdragon 7-series); may also work on some 6xx.
  • Freedreno 8xx: Adreno 8xx (Snapdragon 8 Gen 3 / Gen 4 / Gen 5 / Elite, 7 Gen 3).
  • Freedreno 830/840: Adreno 830/840 (Snapdragon 8 Gen 5 / Elite, e.g. Galaxy S25/S26).
  • TURNIP 740: Adreno 740 (Snapdragon 8 Gen 2). Fixes flickering after the HyperOS 3 / One UI update.
  • TURNIP 7xx: Adreno 7xx (Snapdragon 7-series).
  • TURNIP 710: Adreno 710 (Snapdragon 7 Gen 1).
  • System default: the phone's own Vulkan driver.
  • Your own driver: import it in the side menu, Import/Export Custom Driver.

Controls

  • On-screen controls appear over the game. Change them in the side menu, Controls editor: add, move and resize buttons, sticks, the touchpad and the radial menu, and set what each one presses.
  • The Layout button in the editor opens a menu: load the virtual keyboard and mouse layout, or reset to the default gamepad layout. Import/Export Controls in the side menu shares layouts as .zip files.
  • A physical gamepad works; remap its buttons in the side menu, Gamepad mapper.
  • A physical mouse and keyboard work too. To see the game's own cursor instead of the Android arrow, turn on Lock Cursor to Window in the game's display options. The on-screen mouse follows the same rule.

Quick Save (F10)

Turn on Quick Save (F10) in the instance settings. Pressing F10 in the game then makes a full copy of your world: a point you can return to after a crash or a death.

  • On a big save the copy takes a while and the game may look frozen. It is not: wait and do not close it.
  • One copy is kept per world; each new one replaces the last. Single player only, Build 41 and 42.
  • After a crash Zomdroid offers to return to the copy. You can also restore it from the instance's ⋮ menu, Restore F10 backup.
  • The F10 button is part of the new control layouts. With your own older layout, add it in the Controls editor: input type Keyboard & mouse, binding F10.

Mods

  • Download from Steam, tab Mods, downloads Workshop mods by ID: the number at the end of the Workshop link (…/filedetails/?id=NUMBER). No Steam login needed; several IDs can be separated by spaces. Each mod is saved as a .zip in Downloads/zomdroid.
  • Install them in the side menu, Import Mods. Smart Import finds the mod folder in any .zip structure and fixes Android path issues by itself.
  • Optimization in the side menu has ready settings for the performance mods BetterFPS and Render Less Zombie.
  • Some graphical mods may not display correctly, see Known issues.

Multiplayer and hosting

Joining servers. Build 42 works as is. Build 41 needs the multiplayer libraries. Servers refuse players who run the game in debug mode.

A phone can host in two ways: from inside the game while you play on it, or as a dedicated server with nobody playing on it. Both are experimental.

1. Hosting from the game

Turn on Allow server hosting in the instance settings, launch the game as usual and choose Host in the game.

  • Hosting uses a separate profile: your usual saves, mods and game settings are hidden while the switch is on and come back when you turn it off.
  • On Build 42, give the server at least 2 GB of memory when you create it. That is on top of the memory the game itself needs, so this needs a powerful phone with plenty of RAM.
  • Keep the game open and the screen on while you host.

2. Dedicated server

The phone runs only the server, so all of its power goes to the world, and players join from their own phones. Open the instance's ⋮ menu and tap Start Server.

  • Profile name: pick a profile from the list next to the field and its world continues. A new name creates a new world: the line under the field tells which one it is, and Zomdroid asks before creating a new world. If you type a name by hand, tap Load profile.
  • Mods, sandbox and spawn points are easiest to set up in the game's own Host screen: with Allow server hosting on, create the server settings there, exit the game and pick that profile here.
  • Set the server memory (2048 MB by default), the UDP port, maximum players, how often the world is saved, an optional connection password and the administrator password. Enable mods by their IDs and list maps in load order, both separated by ;. Edit PZ configuration files opens the full server settings.
  • You can close the panel and turn off the screen: the server keeps running with a notification. To shut it down, tap Save and stop and wait until it finishes.
  • Exit the game on this phone before starting the server; while the server runs, the game cannot be launched. Build 41 needs the multiplayer libraries.

3. Letting players in

  • Same Wi-Fi: friends join at the host phone's Wi-Fi address.
  • Over the internet: the router must forward the server's UDP port, 16261 by default, to the host phone. Enable UPnP on the router, or add the forwarding by hand. The status line shows whether the port was opened and your external address; tap it for details.
  • On mobile data the carrier does not let connections in, so players on the internet cannot reach the server directly. Players connected to the host phone's Wi-Fi hotspot can join at its address in that network. Players elsewhere need extra setup in another app: a shared virtual network such as ZeroTier or Tailscale on every phone.

Additional libraries (Build 42.20+)

Some of the game's libraries run through box64 emulation. In the instance settings, card Additional libraries, you can install native ARM64 libraries from the macOS version of the game instead: they need no emulation, so the phone spends less memory and CPU on them. Experimental.

  • From Steam downloads them if you own the game; From file takes an archive you downloaded earlier.
  • All libraries are on by default. If something goes wrong, turn single ones off under Libraries in use: a library that is off uses its regular version.
  • FMOD in the same list is the game's own Android sound library, not from the macOS version. Nothing to download.

Known issues

Frame rate drops in rain

On some mid-range phones the frame rate drops noticeably during rain. Fix: lower the Dynamic Puddles setting in the game options.

Graphical mods compatibility

Some graphical mods, such as retextures of clothing, hair or vehicles, may not display correctly or may not work at all.

GUI disappears near dismantled vehicles (GL4ES)

On GL4ES, the game UI may disappear if there is a vehicle nearby with 3 or more wheels removed. Workaround: avoid removing more than 2 wheels from any single vehicle. If the UI has already disappeared, moving away from the vehicle or reloading the save should restore it.

Reporting a problem

Open the side menu and tap Report a bug. It collects the logs and your settings into a .zip and opens a message to us: pick your email app, for example Gmail, add a description of the problem and tap Send. Export Game Log saves just the game's own log.
